# Phase 4 — Real-time layer: Channels, relay and geofence events

**Goal:** browsers connect to `/ws/live/`, get a snapshot for their bbox and then at most one
delta per second; aircraft entering/leaving geofences produce `enter`/`exit` events that are
stored in `geofence_events` and broadcast. Contract: ICD §4.3, §5, §6.

## Architecture

```
ingest ──positions.batch──▶ relay (asyncio management command)
                              ├─ LiveState: coalesce batches, flush ≤ 1/s → group "live" (live.delta)
                              ├─ one PostGIS query per batch (unnest arrays + ST_Contains)
                              │    → GeofenceTracker (pure state machine) → enter/exit
                              │    → bulk_create geofence_events → group "live" (live.geofence_event)
backend ──geofences.changed──▶ relay reloads fence names, prunes state of removed fences

group "live" ──▶ LiveConsumer (one per socket, in uvicorn)
                   ├─ subscribe → snapshot from aircraft_latest (DB is the source of truth)
                   ├─ live.delta → Outbox (merged, bounded) → filter by bbox/known → delta
                   ├─ live.geofence_event → Outbox (FIFO, never dropped, hard cap → close 1013)
                   └─ heartbeat every 15 s
```

## Decisions to log

- Backpressure: merge pending deltas instead of drop + snapshot (bounded by live aircraft); ICD 1.4.
- Origin check on WebSockets; clients send `Origin`.
- Aircraft that time out are forgotten by the tracker without an `exit` event.
- Batch geofence check via `unnest` arrays (same pattern as ingest), not a temp table.
- Rebuild tracker on start from the last event per (fence, aircraft) within 24 h, for aircraft still live.
- Versions: channels 4.3.2, channels-redis 4.3.0, pytest-asyncio 1.4.0.

## Tests

- Pure: state (coalesce, unchanged not re-sent, timeout, re-appear), merge, filter (left bbox → remove,
  unknown removes dropped), bbox validation, outbox (merge, priority, cap), tracker (enter, no duplicate,
  exit, re-enter, absent ≠ exit, forget, prune).
- DB: geofence query returns pairs in one query; relay batch handling writes events once; rebuild.
- Consumer (`WebsocketCommunicator`, in-memory channel layer): heartbeat-only before subscribe,
  errors, subscribe → snapshot, delta filtered, empty delta suppressed, geofence events unfiltered.

## Acceptance

`make ws` (ws_tail through nginx) prints a delta every second; a synthetic aircraft entering
LTFM 15 km produces a `geofence_event` and a row in `geofence_events`; `/api/geofence-events` lists it.
