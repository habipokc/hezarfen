# Phase 2 — Go ingest service: implementation plan

**Goal:** ingest produces aircraft state snapshots from one of three sources (live OpenSky, replay of
recorded raw responses, synthetic flights), cleans them, writes them to PostGIS (IF-2) and publishes
`positions.batch/v1` to Redis (IF-3), exposing `/healthz` and `/metrics` (IF-8).

## Package layout (`ingest/internal/`)

| Package | Responsibility | Tests |
|---|---|---|
| `config` | env → validated `Config` (pure `Load(getenv)`) | unit |
| `geo` | `Point`, `BBox`, haversine, initial bearing, great-circle interpolation, destination point | TDD (Istanbul–Ankara ≈ 350 km, bearings, midpoints) |
| `opensky` | `State`/`Snapshot` types, positional-array parser, OAuth2 token manager (mutex, refresh before expiry and on 401), `Client.GetStates` (credits header, 429 → `RateLimitError`, 5xx → exponential backoff) | parser with real fixture + nulls; `httptest` server for 200/429/401/5xx/token refresh |
| `source` | `Source` interface (`Name`, `Next(ctx)`); `Live` (adaptive polling, raw zone gzip), `Replay` (time-shifted, speed factor, loops), `Synthetic` (flight state machine on great circles), `Resolve` for `auto` | flight profile TDD, replay ordering/timing, auto resolution |
| `clean` | ETL rules: null position, bbox, callsign trim, invalid icao24, stale > 15 s, duplicate in snapshot, implied speed > 400 m/s → `[]Record` + per-reason counts | TDD, rule by rule |
| `store` | pgx pool; one transaction per batch: `aircraft` upsert → `aircraft_latest` upsert (newer ts only) → `positions` insert `ON CONFLICT DO NOTHING`, all via `unnest` arrays (one round trip per table) | integration test against PostGIS in a throwaway schema (skips without DB) |
| `publish` | `positions.batch/v1` JSON → Redis `PUBLISH` | message shape unit test |

`cmd/ingest/main.go` wires config → source → clean → store + publish, keeps metrics, and shuts down
gracefully on SIGINT/SIGTERM.

## Steps

1. Dependencies (`pgx/v5`, `go-redis/v9`), `config`, `geo` (TDD).
2. `opensky` parser + client + token manager with `httptest`.
3. `clean` (TDD).
4. `source`: synthetic (profile TDD), replay, live, resolve.
5. `store` + `publish`, main loop, metrics.
6. Container user: ingest runs as the host UID (prod and dev) so `data/raw` files are not root/nonroot-owned.
7. `scripts/record_fixture.sh` + `make record`: anonymous OpenSky snapshots → `ingest/testdata/opensky/`.
8. ICD 1.2 (per-aircraft `ts` in IF-3, extended metrics), DECISIONS, README (live mode setup), ARCHITECTURE.
9. Acceptance: synthetic updates `aircraft_latest` and Redis receives messages (`redis-cli SUBSCRIBE`);
   replay plays the recorded fixture; `go test ./...`, `go vet`, gofmt clean; full `make test`/`make lint`.
10. Learn `05-go-temelleri.md`, `06-adsb-ve-etl.md`; closing ritual.
