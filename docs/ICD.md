# Hezarfen — Interface Control Document (ICD)

- **Version:** 1.2 (Phase 2)
- **Status:** Baseline. Every component is built against this document; code that disagrees with it is a bug in either the code or this document, and must be resolved by updating both in the same change.
- **Machine-readable REST contract:** OpenAPI 3 schema generated by drf-spectacular at `/api/schema/` (Swagger UI at `/api/docs/`) from Phase 3 on. Where this document and the generated schema disagree on REST details, the generated schema wins and this document is corrected.

## 2. Units and coordinate conventions (apply to every interface)

| Quantity | Unit / convention |
|---|---|
| Coordinates | WGS84, **EPSG:4326**, always ordered **lon, lat** (GeoJSON order, RFC 7946) |
| Bounding box | `[minLon, minLat, maxLon, maxLat]` (GeoJSON bbox order) |
| Altitude | metres (`baro_alt`, `geo_alt`, terrain elevation, AGL) |
| Speed | metres per second |
| Vertical rate | metres per second, positive = climbing |
| Heading | degrees clockwise from true north, `[0, 360)` |
| Time | Unix seconds, UTC, integer unless stated otherwise |
| Aircraft id | `icao24`: 6 lowercase hex characters, e.g. `"4baa0f"` |
| Callsign | trimmed string, `null` if unknown |
| Missing values | JSON `null`; fields are never omitted from a documented object |

The OpenSky source (IF-1) delivers the same units, so ingest does not convert units — it only reorders positional arrays into named fields.

## 3. IF-2 — Database tables written by ingest

The schema is owned by Django migrations (`backend/tracking/migrations`). Table names are fixed with `Meta.db_table` so the Go service can address them directly. Ingest must not issue DDL.

| Table | Ingest operation | Conflict rule |
|---|---|---|
| `aircraft` | upsert identity (`icao24`, `callsign`, `origin_country`, `category`, `first_seen`, `last_seen`) | `ON CONFLICT (icao24) DO UPDATE` — keeps `first_seen`; `last_seen = GREATEST(old, new)`; `callsign`, `origin_country`, `category` take the new value unless it is null |
| `aircraft_latest` | upsert latest state per aircraft | `ON CONFLICT (icao24) DO UPDATE` only when the incoming `ts` is newer |
| `positions` | append history | `ON CONFLICT (icao24, ts) DO NOTHING` — makes re-ingesting the same snapshot idempotent |

Geometry is written as `ST_SetSRID(ST_MakePoint(lon, lat), 4326)`. Timestamps are `timestamptz` in the database and Unix seconds on every wire format.

One ingest cycle is one transaction: `aircraft`, then `aircraft_latest`, then `positions`, each a single `INSERT … SELECT FROM unnest(<column arrays>)` statement, sent together as one pipelined batch. `source` records the resolved mode of the cycle.

**Columns** (from `backend/tracking/models.py`; units as in §2):

| Table | Column | Type | Null | Notes |
|---|---|---|---|---|
| `aircraft` | `icao24` | `varchar(6)` | no | primary key |
| | `callsign` | `varchar(8)` | yes | |
| | `origin_country` | `varchar(64)` | yes | |
| | `category` | `smallint` | yes | OpenSky emitter category |
| | `first_seen`, `last_seen` | `timestamptz` | no | |
| `aircraft_latest` | `icao24` | `varchar(6)` | no | primary key, FK → `aircraft` (deferred); upsert `aircraft` first in the same transaction |
| `aircraft_latest`, `positions` | `ts` | `timestamptz` | no | position timestamp |
| | `geom` | `geometry(Point, 4326)` | no | GiST index |
| | `baro_altitude`, `geo_altitude` | `double precision` | yes | m |
| | `velocity` | `double precision` | yes | m/s |
| | `heading` | `double precision` | yes | degrees |

## 4. IF-3 — Redis `positions.batch` (ingest → relay)

- **Channel:** `positions.batch`
- **Delivery:** Redis pub/sub, fire-and-forget. A relay that is not subscribed misses the message; the database remains the source of truth, so a restarted relay rebuilds its state from PostGIS rather than from Redis.
- **Frequency:** one message per ingest cycle (live: every poll; replay: per recorded snapshot; synthetic: every tick, 1–5 s).

### 4.1 Message

```json
{
  "schema": "positions.batch/v1",
  "source": "synthetic",
  "ts": 1791187200,
  "aircraft": [
    {
      "icao24": "4baa0f",
      "callsign": "THY7AB",
      "lon": 28.8146,
      "lat": 41.2753,
      "baro_alt": 3350.0,
      "geo_alt": 3420.5,
      "velocity": 152.3,
      "heading": 87.4,
      "vrate": 6.5,
      "on_ground": false,
      "squawk": "2341",
      "category": 4,
      "ts": 1791187198
    }
  ]
}
```

| Field | Type | Notes |
|---|---|---|
| `schema` | string | Always `"positions.batch/v1"` for this version |
| `source` | `"live"` \| `"replay"` \| `"synthetic"` | Resolved mode (never `"auto"`) |
| `ts` | integer | Ingest cycle time (Unix s) |
| `aircraft[]` | array | Only cleaned records (§4.2); may be empty |
| `icao24` | string | required |
| `callsign` | string \| null | trimmed |
| `lon`, `lat` | number | required, inside the configured region bbox |
| `baro_alt`, `geo_alt` | number \| null | metres |
| `velocity` | number \| null | m/s over ground |
| `heading` | number \| null | true track, degrees |
| `vrate` | number \| null | m/s |
| `on_ground` | boolean | |
| `squawk` | string \| null | 4 octal digits as a string, e.g. `"7700"` |
| `category` | integer \| null | OpenSky aircraft category (0–20) |
| `ts` | integer | Position time of this aircraft (Unix s), ≤ the envelope `ts`. Added in 1.2 (backward-compatible) |

### 4.2 Cleaning guarantees (ingest side)

Records reaching IF-2 and IF-3 have: a non-null position; a position inside the region bbox; a trimmed callsign; a `time_position` no older than 15 s relative to the snapshot; and an implied speed from the previous accepted fix of the same aircraft of at most 400 m/s. Records with an invalid `icao24` (not 6 hex characters after lower-casing) and second occurrences of the same `icao24` within one snapshot are dropped as well. Rejected records are counted (`rejected_total` in IF-8), never published; impossible jumps are also logged at `WARN`.

In `replay` mode cleaning runs on the recorded timestamps; the accepted records are then re-timed onto the wall clock (`ts_wall = segment_start_wall + (ts_recorded − segment_start_recorded) / REPLAY_SPEED`), so consumers cannot tell replay from live.

### 4.3 Redis `geofences.changed` (backend → relay)

Published by the backend after any geofence create/update/delete so the relay reloads its geofence cache.

```json
{ "schema": "geofences.changed/v1", "ts": 1791187200, "geofence_id": 3, "action": "created" }
```

`action` is one of `"created"`, `"updated"`, `"deleted"`. The relay treats any message as "reload everything"; the fields exist for logging.

## 5. IF-4 — Channels layer (relay → WebSocket consumers)

Internal to the backend; documented so the relay and consumer evolve together.

| Group | Event `type` | Payload |
|---|---|---|
| `live` | `live.delta` | `{ "ts", "upserts": [Aircraft], "removes": [icao24] }` — unfiltered; each consumer filters by its own bbox |
| `live` | `live.geofence_event` | `GeofenceEvent` object (§6.3) |

The relay publishes at most once per second (coalescing all batches received in that second).

## 6. IF-5 — WebSocket `/ws/live/`

- **URL:** `ws://<host>:8800/ws/live/` (via nginx; `wss://` behind TLS).
- **Encoding:** one JSON object per text frame, discriminated by `type`.
- **Session:** after connecting, the client must send `subscribe`. Until then the server sends only `heartbeat`. A new `subscribe` replaces the previous bbox and triggers a fresh `snapshot`.

### 6.1 Client → server

| `type` | Fields | Notes |
|---|---|---|
| `subscribe` | `bbox: [minLon, minLat, maxLon, maxLat]` | Validation: 4 finite numbers, `-180 ≤ lon ≤ 180`, `-90 ≤ lat ≤ 90`, `min < max`. Invalid → `error` message, connection stays open |

```json
{ "type": "subscribe", "bbox": [27.5, 40.4, 30.2, 41.6] }
```

### 6.2 Server → client

**`Aircraft` object** (shared by `snapshot` and `delta`):

```json
{
  "icao24": "4baa0f", "callsign": "THY7AB",
  "lon": 28.8146, "lat": 41.2753,
  "baro_alt": 3350.0, "geo_alt": 3420.5,
  "velocity": 152.3, "heading": 87.4, "vrate": 6.5,
  "on_ground": false, "squawk": "2341", "category": 4,
  "ts": 1791187200
}
```

| `type` | Fields | When |
|---|---|---|
| `snapshot` | `ts`, `aircraft: [Aircraft]` | After every valid `subscribe`; all aircraft seen in the last 60 s inside the bbox |
| `delta` | `ts`, `upserts: [Aircraft]`, `removes: [icao24]` | At most 1/s. `upserts`: aircraft inside the bbox whose state changed. `removes`: aircraft not seen for 60 s, or that left the bbox. Empty deltas are not sent |
| `geofence_event` | `GeofenceEvent` (§6.3) | Every enter/exit, **not** filtered by bbox |
| `heartbeat` | `ts` | Every 15 s, so proxies and clients can detect dead connections |
| `error` | `code`, `message` | Invalid client message. Codes: `invalid_json`, `unknown_type`, `invalid_bbox` |

```json
{ "type": "delta", "ts": 1791187201,
  "upserts": [ { "icao24": "4baa0f", "lon": 28.82, "lat": 41.276, "...": "..." } ],
  "removes": ["4b1812"] }
```

### 6.3 `GeofenceEvent`

```json
{
  "type": "geofence_event",
  "id": 1042,
  "geofence": { "id": 1, "name": "LTFM 15 km" },
  "icao24": "4baa0f",
  "callsign": "THY7AB",
  "event": "enter",
  "ts": 1791187201,
  "lon": 28.79,
  "lat": 41.18
}
```

`event` is `"enter"` or `"exit"`. The same event is stored in `geofence_events` before it is broadcast, so `id` can be used against the REST API.

### 6.4 Backpressure

The server never blocks on a slow client. If a client's outbound queue is full, older `delta` messages are dropped and the next delta is replaced by a `snapshot` so the client converges again. `geofence_event` messages are never dropped while the connection is alive. (Policy details: `docs/DECISIONS.md`.)

## 7. IF-6 — REST API `/api/`

All responses are JSON; geometry-bearing collections are GeoJSON `FeatureCollection`s with `[lon, lat]` coordinates.

### 7.1 Error format

Every non-2xx response has this body:

```json
{ "error": { "code": "invalid_bbox", "message": "bbox must be minLon,minLat,maxLon,maxLat", "details": {} } }
```

| HTTP | `code` examples |
|---|---|
| 400 | `invalid_bbox`, `invalid_parameter`, `window_too_large`, `invalid_geometry` |
| 404 | `not_found` |
| 503 | `unavailable` (dependency down) |

### 7.2 Endpoints

| Method & path | Parameters | Response | Phase |
|---|---|---|---|
| `GET /api/health` | — | `{ "status": "ok"\|"degraded", "checks": {...} }`, 200 or 503 | 0 |
| `GET /api/aircraft/live` | `bbox=minLon,minLat,maxLon,maxLat` (optional; default region) | FeatureCollection of Points; properties = `Aircraft` fields. Aircraft seen in the last 60 s | 3 |
| `GET /api/aircraft/{icao24}/` | — | Feature: latest state + `province` (name or null) + `nearest_airport` (`ident`, `name`, `distance_m`) | 3 |
| `GET /api/aircraft/{icao24}/track` | `since=<unix>` (default now − 30 min) | Feature with a LineString ordered by time; properties `start_ts`, `end_ts`, `points` | 3 |
| `GET /api/playback` | `start`, `end` (Unix, window ≤ 2 h), `bucket` (seconds, default 10) | `{ "start", "end", "bucket", "frames": [ { "ts", "aircraft": [Aircraft] } ] }`, gzip-compressed by the proxy when large | 3 |
| `GET /api/geofences/` | `active=true\|false` | FeatureCollection of Polygons; properties `id`, `name`, `kind`, `active`, `created_at` | 3 |
| `POST /api/geofences/` | body: GeoJSON Feature with Polygon geometry, properties `name`, `active` | 201 + created Feature. Geometry validated with shapely: must be valid (or made valid), area within limits, must intersect the region bbox | 3 |
| `PATCH /api/geofences/{id}/` | partial properties and/or geometry | 200 + Feature | 3 |
| `DELETE /api/geofences/{id}/` | — | 204 | 3 |
| `GET /api/geofence-events` | `since=<unix>`, `geofence=<id>` | Paginated list of `GeofenceEvent` | 3 |
| `GET /api/provinces/` | — | FeatureCollection, geometry simplified with `ST_Simplify` | 3 |
| `GET /api/airports/` | `type=large_airport,...` | FeatureCollection of Points | 3 |
| `GET /api/stats` | — | `{ "active_aircraft", "events_last_hour", "ingest": {...} }` | 3 |
| `GET /api/terrain/elevation` | `lon`, `lat` | `{ "lon", "lat", "elevation_m": number\|null }` (null = nodata) | 7 |
| `GET /api/schema/`, `/api/docs/` | — | OpenAPI schema, Swagger UI | 3 |

### 7.3 Pagination

List endpoints that can grow unbounded (`geofence-events`) use cursor-style pagination: `{ "next": <url|null>, "previous": <url|null>, "results": [...] }`.

## 8. IF-8 — Ingest `/metrics` and `/healthz`

Served on `ingest:8080` (compose network only; not routed by nginx).

- `GET /healthz` → `200 {"status":"ok"}` while the process is running.
- `GET /metrics` →

```json
{
  "mode": "synthetic",
  "started_at": "2026-10-05T08:00:00Z",
  "last_poll_at": "2026-10-05T08:10:05Z",
  "credits_remaining": null,
  "last_batch_size": 64,
  "error_count": 0,
  "cycles": 312,
  "poll_interval_seconds": 2,
  "last_positions_inserted": 64,
  "last_subscribers": 1,
  "rejected_total": { "stale": 3, "impossible_jump": 1 }
}
```

`last_poll_at` and `credits_remaining` are `null` until known (credits are only known in `live` mode).

| Field | Meaning |
|---|---|
| `mode` | Resolved source mode (`live` \| `replay` \| `synthetic`) |
| `last_poll_at` | Wall-clock time of the last completed cycle |
| `credits_remaining` | Last `X-Rate-Limit-Remaining` from OpenSky |
| `last_batch_size` | Cleaned records in the last cycle |
| `error_count` | Source, database and Redis failures since start |
| `cycles` | Completed cycles since start (added in 1.2) |
| `poll_interval_seconds` | Current interval: live (adaptive 10 → 30 s) or synthetic tick; `0` in replay (added in 1.2) |
| `last_positions_inserted` | New `positions` rows in the last cycle; lower than the batch when fixes repeat (added in 1.2) |
| `last_subscribers` | Redis subscribers that received the last message (added in 1.2) |
| `rejected_total` | Cumulative rejections per cleaning rule (§4.2), keys: `invalid_icao24`, `no_position`, `out_of_bbox`, `stale`, `duplicate`, `impossible_jump` (added in 1.2) |

## 9. Versioning rules

1. Every Redis message carries a `schema` field `<name>/v<N>`.
2. **Backward-compatible** changes (adding an optional field, adding a new message `type`) keep the version; consumers must ignore unknown fields and unknown `type`s.
3. **Incompatible** changes (removing or renaming a field, changing a unit or meaning) require a new schema version (`positions.batch/v2`). During migration the producer publishes both versions until all consumers are upgraded.
4. REST breaking changes require a new path prefix (`/api/v2/`). The WebSocket path follows the same rule (`/ws/v2/live/`).
5. Any change to this document is recorded in the change log below.
